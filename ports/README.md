# Music Player — матрица port.9

Все текущие варианты имеют версию порта **port.9** и функциональность исходного порта 26.2.
Это девять исходных профилей, из которых собираются 15 точных сборок и затем
восемь основных JAR. Один основной JAR может поддерживать несколько версий Minecraft.
После сборки точные JAR размещаются в `dist/port.9/exact/` как резерв для проверки.

Основные JAR объединяются только при полном совпадении байткода, вложенных
библиотек и игровых ресурсов между исходными сборками. Для диапазонов в

форматом ресурсов в `pack.mcmeta` указаны поддерживаемые форматы.
Fabric API для каждой версии игры берите из `targets.json` — запись зависимости
в многоверсионном JAR задаёт лишь общий нижний предел.

0.145.1 для 26.1, 0.145.4 для 26.1.1 и 0.155.3 для 26.1.2.

## Сборка

Для сборки нужен JDK 25; старые профили компилируют собственные модули с `--release 21`.
Fabric Loader: 0.19.5. Точные зависимости Fabric API указаны в `targets.json`.
Для 26.2 сохранена исходная Fabric API 0.156.0+26.2.

Проще всего запустить из корня проекта `build-menu.bat` в Windows или
`sh build-menu.sh` в Linux/macOS. В меню перечислены восемь совместимых диапазонов:
один пункт соответствует одному итоговому JAR. Пункт 9 собирает всё,
пункт C очищает созданные файлы. Например, единый пункт 1.21.6–1.21.8
соберёт эти три точные версии для одного общего JAR. Готовые файлы появятся
в `dist/port.9/`. Сборки выполняются по одной, без параллельного Gradle.

Для автоматического запуска доступны `--list`, `--group 1.21.6-1.21.8`, `--all`,
`--clean` и `--clean --dry-run`. Очистка удаляет только созданное внутри проекта:
`build`, `.gradle`, временные кеши, логи, тестовые каталоги запуска и весь
`dist/port.9`. Исходники и настройки сохраняются. Старые бинарники port.7
не воспроизводятся точно из нынешних исходников port.9, поэтому их следует
архивировать отдельно вне дерева проекта. Общий кеш `~/.gradle`
не затрагивается, поскольку им пользуются и другие проекты.

Из корня проекта в PowerShell:

```powershell
.\ports\Build-All.ps1
python .\ports\package_ports.py
```

Одна версия:

```powershell
.\ports\Build-All.ps1 -Versions '1.21.8'
```

Отдельная задача Gradle:

```powershell
.\ports\Build-Target.ps1 -Group '1.21.6-1.21.8' -Version '1.21.8' -Tasks compileJava
```

Общий скрипт выполняет только одну сборку одновременно, ограничивая расход памяти.
Выход отдельного профиля: `ports/<профиль>/build/<Minecraft>/libs/`.
В `dist/port.9/` попадают восемь основных JAR после проверки всей матрицы;
15 точных версий остаются в `dist/port.9/exact/`.
`-thin`, `-dev`, `-sources` и промежуточные shaded JAR распространять нельзя.

`package_ports.py` проверяет точные версии, наличие аудиомодуля и вложенных зависимостей,
допустимый байткод Java, ресурсы, лицензии и remapping для старых версий.
Перед объединением он сравнивает все файлы архивов, кроме `fabric.mod.json`,
`pack.mcmeta` и версии игры в манифесте. Он также создаёт `manifest.json`
и `SHA256SUMS.txt` для обоих наборов.

## Сортировка port.9

В плейлисте под управлением воспроизведением доступна кнопка **Сортировка**.
Шесть вариантов: название, исполнитель или имя файла / URI, по возрастанию
и убыванию. Регистр не влияет на порядок; числа сравниваются естественно:
`2` идёт перед `10`. Новый порядок сохраняется сразу. Дубликаты и ошибки
загрузки сохраняются, текущая музыка не прерывается. Вложенные онлайн-плейлисты
перемещаются целиком, без изменения порядка треков внутри них.

При загрузке папки обычные файлы сортируются по имени до чтения метаданных,
а результаты появляются в том же порядке независимо от скорости загрузки.
**Добавить всё** доступно после завершения загрузки. Старые ответы игнорируются
при новом поиске или выходе с экрана. Подписи добавлены во все девять языков.

Автономные проверки настоящего кода сортировки, плейлиста и сериализации:

```powershell
python .\ports\test_sorting.py
python .\ports\test_sorting.py 1.21.2-1.21.3
```

Проверки выполняются без Minecraft и сети; библиотеки Gson и Commons Lang
берутся из кеша Gradle после сборки.

## Сохранённое исправление port.8

YouTube регистрируется при создании плеера до общего HTTP-источника.
Раньше он добавлялся только после входа в аккаунт, уже после HTTP: сохранённые
watch-ссылки при новом запуске попадали в распознавание аудиофайлов и возвращали
`Unknown file format.`. OAuth теперь включает уже зарегистрированный источник,
не меняя порядок источников и не добавляя дубликаты. Формат сохранённых плейлистов
не меняется; удалять плейлисты или заново добавлять песни не нужно.

Автономная регрессионная проверка использует настоящий диспетчер Lavaplayer и
TrackSearch с подставными сетевыми источниками. Она воспроизводит ошибку старого
порядка, проверяет три новых экземпляра плеера с прежними ссылками, восстановление
и повтор OAuth, поиск, плейлисты и доступность обычных HTTP-аудиофайлов.
Она не обращается к YouTube/Google и не запускает Minecraft:

```powershell
python .\ports\test_audio_routing.py 1.21.2-1.21.3
python .\ports\test_audio_routing.py 26.3
```

Старые готовые сборки port.7 храните в отдельном архиве вне исходников.

## Установка и границы проверки

Выберите один основной JAR, в диапазон которого входит версия Minecraft, установите Fabric Loader 0.19.5
и Fabric API из `targets.json`. Удалите из папки mods другой вариант Music Player,
чтобы одновременно не загружать два мода с одинаковым ID `musicplayer`.

Автор сборки Minecraft не запускал. Пользователь предоставил лог успешного запуска
предыдущей версии port.8 на Minecraft 26.2 без ошибок. Новая port.9 этим логом не проверена.
Успешная компиляция и проверка архива не означают проверенную работу GUI, аудио или YouTube.
Пользователь самостоятельно проверяет запуск, горячие клавиши, HUD, текстовый ввод,
плейлисты, файловые диалоги, воспроизведение, настройки и закрытие процесса.

Внешние YouTube OAuth/cipher-сервисы и их ограничения остаются такими же, как в исходном port.7.
Исправление завершения аудио- и фоновых потоков сохраняется во всех исходных профилях.
