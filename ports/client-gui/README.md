# Проверка GUI в настоящем Minecraft-клиенте

Для port.10.2 завершены проверки всех 16 версий Forge: 13 запусков готового
release JAR и три запуска исходников в dev-клиенте. Дальнейшие запуски
остановлены по просьбе сопровождающего. Результаты: [отчёт port.10.2](../verification/README.md).
Исторический `last-results.json` относится к предыдущему релизу.

Это интеграционный сценарий для 50 точных сочетаний из `targets.json` и
`loader-targets.json`: 17 Fabric, 16 Forge, 17 NeoForge. Java-агент вызывает
обработчики мыши/клавиатуры на render thread Minecraft, проверяет изменения
состояния и сохраняет настоящие скриншоты клиента. Windows-ввод не автоматизируется.

Проверяются открытие окон, создание/удаление плейлиста, загрузка WAV через путь и
локальный HTTP, добавление одного/всех треков, кнопки импорта файла/папки,
перемещение/удаление строк, поиск по спискам, запуск/остановка плейлиста,
пауза, пропуски, shuffle/repeat, перемотка, громкость, все шесть вариантов
сортировки, переключатели/ползунки/язык/масштаб в настройках, выбор строки
аудиоустройства, окно входа с возвратом через Skip и все десять полос эквалайзера.

## Ограничения

- Системный диалог выбора файла/папки подменяется только на границе LWJGL:
  TinyFileDialogs или SDL возвращает путь к WAV/папке. Сама GUI-кнопка,
  callback импорта, загрузчик треков и добавление в плейлист выполняются реально.
  Внешний вид и навигация Windows-диалога не проверяются.
- Вход в аккаунты, OAuth и доступность сторонних музыкальных сервисов не проверяются.
- Это проверка GUI и загрузки треков; качество звука и игровой мир не проверяются.
- Современные NeoForge (16 версий) и Forge на ForgeGradle 7 (13 версий)
  загружают готовый release JAR и вложенные аудиозависимости в dev-клиенте.
  Fabric, старые Forge и NeoForge 1.20.1 запускают
  скомпилированные исходники dev-клиента. Production-remapping отдельно
  проверяется упаковщиками `package_ports.py` и `package_loaders.py`.

## Повторный запуск (Windows)

Нужны Python 3, PowerShell 7, JDK 17/21/25 и рабочий OpenGL-драйвер.
Сначала соберите нужный профиль через `Build-Target.ps1`, чтобы Gradle скачал
зависимости и ASM 9.10.1. Создание агента использует JDK из `JAVA_HOME`,
`%USERPROFILE%/.jdks` или `%ProgramFiles%/Java`.

```powershell
python ports/client-gui/build_agent.py
python ports/client-gui/run_matrix.py --loader forge --version 1.20.1
python ports/client-gui/run_matrix.py --loader neoforge --version 1.21.1
python ports/client-gui/run_matrix.py --resume
```

Клиенты запускаются последовательно. Не запускайте два сценария одновременно.
Агент нельзя пересобирать во время запущенного Minecraft-клиента.
`--no-build` пропускает сборку и подходит только для уже собранного профиля.
`--resume` пропускает успешные записи того же релиза с тем же агентом и
SHA-256 исходников/конфигурации профиля; при запуске release JAR также сверяется
SHA-256 самого архива. Изменённые профили проверяются повторно. Агент и тестовые WAV создаются в `.cache/client-tests`,
драйвер автоматически поднимает и закрывает локальный HTTP-сервер.

Результаты: `.cache/client-tests/matrix-results.json`, логи каждой пары,
`<loader>-<version>/gui-result.txt` и `screenshots/*.png`. Используется отдельная
тестовая конфигурация и плейлист. `last-results.json` содержит результаты
последнего опубликованного прогона, когда такой прогон сохранён.

## Устройство тестового запуска

`client-test.init.gradle` настраивает тестовый клиент. Старые Forge объединяют
ресурсы, классы и аудио API через официальный Bootstrap Dev; метаданные модуля
находятся только в тестовой папке. В ForgeGradle 7 тест удаляет исходники и
отдельный аудио API из runtime classpath, чтобы загрузить их из готового JAR.
`GuiScenario` сохраняет загрузчик контекста игры, чтобы Forge не трансформировал
классы событий из постороннего classloader. `PickerFixture` меняет только ответ
нативного chooser, оставляя GUI, рендер и аудиодвижок настоящими.

Для Fabric агент создаётся без копии ASM: используется библиотека загрузчика,
чтобы Fabric не отклонял дублирующиеся классы. Клиент запускается на Java 17
для 1.20.1, Java 21 для 1.21.x и Java 25 для 26.x. В 26.3 сценарий использует
SDL-коды мыши и клавиатуры; в более старых клиентах — GLFW.

`agent-history.json` сохраняет SHA-256 предыдущих проверенных агентов и точные
пары, результаты которых совместимы после добавления новых API-переходов.
Исходный SHA-256 каждого запуска остаётся в отчёте; результаты не переписываются
как будто они были получены другим бинарным агентом.

В SDL-диалогах 26.3 тестовый callback разрешается через системный classloader,
поскольку Fabric Knot изолирует игровые классы от Java-агента. Это изменение
только тестового chooser-моста; код мода и LWJGL callback импорта остаются настоящими.
